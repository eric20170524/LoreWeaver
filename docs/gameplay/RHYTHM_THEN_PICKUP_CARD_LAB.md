# 节奏后拾取 Card Lab

第二十张 `rhythm_then_pickup` 使用共享 RuntimeKernel / core Adapter，入口 `?card=rhythm_then_pickup`。默认间隔 1200ms，完美窗口 ±90ms、有效窗口 ±180ms，命中 12 拍后进入拾取阶段。20 秒内拾取 5 个紫色目标获胜，目标有停留期限，超时失败。节奏阶段无死亡/倒计时，可失误后继续或撤退。

修复圆环对象点击加场景点击的双重判定，以及同拍无限连点累计命中。每个最近节拍最多判定一次，提前失误也占用该拍；圆环最大/最亮位置现在对应节拍中心，原视觉峰值偏离了半拍。节拍时间通过运行中的 delta 累计，暂停不累计，不再用全局 scene.time.now 的差值计拍。完美、有效和失误的颜色反馈保留。

拾取只接受运行中、第二阶段、当前且活跃的目标。暂停、过期或重复回调不能计数；最后一个目标结算后立即返回，避免访问已销毁 UI。反馈 timer、下一次生成 timer、各目标过期 timer、键盘监听和对象引用均显式清理。宿主 goalValue=0，第一阶段分数不会提前获胜。

点击圆环判节奏，点击紫色目标拾取；空格在第一阶段判节奏，在第二阶段拾取最早出现的目标。键盘按 DOM 事件对象去重，长按 repeat 不追加动作。目标生成范围避开宿主 HUD。

公开 10 项参数，保留既有最多 40 拍和 20 个目标的范围。窗口满足“完美 ≤ 有效 < 半拍”；间隔和停留的最大值不少于最小值；拾取时间至少为 `目标数 × 最长生成间隔 + 0.2 秒`。试验场拒绝不合法组合，适配器直接调用则归一为有限可供给参数。默认配置未缩短。

```sh
node productize/jobs/check-rhythm-pickup-runtime.mjs
node productize/jobs/run-rhythm-pickup-card-lab-e2e.mjs
npx tsc --noEmit
```

八项状态机回归覆盖单拍判定、视觉与窗口、暂停累计时钟、单次阶段切换与拾取身份、成功和同步销毁、过期/超时、键盘去重、参数上界及权限。

浏览器七场景：默认纯键盘两阶段通关、一次点击只算一拍/连点不加分/离拍失误、配置拾取超时、两阶段暂停及三次重开、非法窗口与最大配置启动/撤退、390px 默认触屏两阶段通关、file:// 默认鼠标两阶段通关。最大配置只检查启动参数和撤退，不宣称完成 40 拍/20 目标全程。浏览器读取当前圆环节拍位置和可见目标坐标，只发送实际输入，不修改状态或加速时间。
